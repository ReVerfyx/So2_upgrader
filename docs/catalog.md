# Каталог предметов: загрузка своих скинов и цен

Каталог намеренно не «зашит» в код: цены на скины Standoff 2 меняются, а
изображения у каждой площадки свои. Предметы загружаются файлом.

## Формат файла

JSON: либо массив предметов, либо объект `{ "items": [...] }`.

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `slug` | да | Уникальный код: строчная латиница, цифры, дефис (2–64 символа). По нему предмет обновляется при повторном импорте |
| `name` | да | Отображаемое название, 2–120 символов |
| `weapon` | да | Тип оружия: `AKR`, `M4`, `AWM`, `USP`, `Нож`, `Перчатки` и т.д. |
| `rarity` | да | `common`, `rare`, `epic`, `legendary`, `arcane`, `contraband` |
| `condition` | нет | `factory_new`, `minimal_wear`, `field_tested`, `well_worn`, `battle_scarred` (по умолчанию `field_tested`) |
| `priceCoins` | да | Цена в монетах: `1250` или `1250.50`. **1 монета = 1 ₽** |
| `imageUrl` | нет | Ссылка на изображение: путь `/items/...` или полный адрес `https://...` |
| `description` | нет | Описание, до 500 символов |
| `isActive` | нет | Показывать ли предмет в каталоге (по умолчанию `true`) |
| `isWithdrawable` | нет | Можно ли выводить (по умолчанию `true`) |

Пример — `database/catalog.example.json`.

## Откуда взять каталог

Прайса под рукой может не быть, поэтому в проекте есть сборщик каталога —
`npm run catalog:*`. Он готовит файл нужного формата четырьмя способами.

### 1. Сгенерировать из справочника оружия

```bash
npm run catalog:generate --workspace backend
```

Берёт `database/weapons.json` — список оружия Standoff 2 по категориям
(автоматы, снайперские, ПП, пистолеты, дробовики, ножи, перчатки, гранаты),
набор расцветок и базовые цены по редкости. На выходе — `catalog.json`
примерно на 850 предметов с ценами от 9 до 59 000 монет.

Правится всё в одном файле: добавьте своё оружие, расцветки и цены.

| Поле в `weapons.json` | Что задаёт |
| --- | --- |
| `categories[].weapons[].priceFactor` | Множитель цены для конкретного ствола |
| `finishes` | Названия расцветок по редкостям |
| `basePrices` | Базовая цена редкости в монетах |
| `conditionFactors` | Коэффициенты состояния (ПСЗ дороже, ЗВБ дешевле) |

Итоговая цена = `базовая × priceFactor × коэффициент состояния × разброс 0.80–1.24`.
Разброс детерминирован (зависит от slug), поэтому цены не «прыгают» между запусками.

### 2. Собрать с сайта-прайса

Сначала посмотрите, что распознаётся, ничего не записывая:

```bash
npm run catalog:inspect --workspace backend -- --url https://пример.ру/market
```

Скрипт пробует четыре стратегии подряд и печатает, сколько записей дала каждая:

1. **JSON внутри страницы** — `__NEXT_DATA__`, `window.__NUXT__`,
   `<script type="application/json">` (самый надёжный источник);
2. **HTML-таблицы** — ищет столбцы с названием и ценой;
3. **Повторяющиеся карточки** — блоки с одинаковым классом;
4. **Ваши CSS-селекторы** из файла конфигурации.

Если автоматика не справилась, сохраните страницу в браузере (Ctrl+S) и
подберите селекторы:

```bash
npm run catalog:scrape --workspace backend -- --file page.html --config database/scraper.example.json
```

Полезные параметры:

| Параметр | Назначение |
| --- | --- |
| `--url` / `--file` | Адрес страницы или сохранённый HTML |
| `--config <файл>` | Свои CSS-селекторы (`database/scraper.example.json`) |
| `--price-multiplier 0.5` | Если на сайте цены не в рублях (например, голда) |
| `--rarity legendary` | Задать редкость всем предметам сразу |
| `--limit 500` | Ограничить количество |
| `--out my.json` | Куда записать |

Тип оружия, редкость и состояние определяются автоматически по названию и
цене: `Керамбит | Рубин` → оружие «Нож»; цена 54 060 → редкость «контрабанда».
Названия с цифрами (`M4`, `P350`, `Tec-9`, `M9 Байонет`) за цену не принимаются.

### 3. Из таблицы CSV

Подходит, когда прайс ведётся в Excel или Google Таблицах:

```bash
npm run catalog:csv --workspace backend -- prices.csv
```

Нужны колонки с названием и ценой — заголовки распознаются и по-русски
(`Название;Цена;Изображение;Редкость`), разделитель `,` или `;`.

### 4. Написать файл руками

Формат описан ниже, пример — `database/catalog.example.json`.

## Загрузка

```bash
# Разработка
npm run items:import --workspace backend -- ./database/catalog.example.json

# Production (после сборки)
npm run items:import:prod --workspace backend -- ./catalog.json

# Отключить предметы, которых нет в файле
npm run items:import --workspace backend -- ./catalog.json --deactivate-missing
```

Импорт выполняется одной транзакцией: при ошибке в файле ничего не меняется.
Некорректные записи перечисляются в выводе, остальные применяются.

Также каталог можно править вручную в админ-панели (раздел «Предметы»):
там же меняется ссылка на изображение конкретного предмета.

## Изображения

Есть три способа:

1. **Свой CDN или папка.** Указывайте полный адрес в `imageUrl`.
2. **Локальные файлы.** Положите картинки в `public/items/` и указывайте
   путь вида `/items/karambit-fade.png`.
3. **Общий префикс.** Задайте `ITEMS_IMAGE_BASE_URL=https://cdn.example.com/so2`
   — тогда демонстрационный каталог соберёт пути как `<base>/<slug>.png`.

Если изображение не задано, подставляется нейтральная заглушка по типу
оружия и редкости из `public/items/` — их не нужно ничего скачивать.

> Не размещайте чужие изображения без прав на использование. Официальные
> материалы Standoff 2 принадлежат Axlebolt; для витрины используйте
> собственные рендеры, скриншоты или лицензированные изображения.

## Цены и валюта

* Внутренняя валюта — **монеты**, 1 монета = 1 ₽.
* В базе суммы хранятся в копейках (`price_minor`, `amount_minor`) типом
  `BIGINT` — без чисел с плавающей точкой.
* Пополнение приходит в TON и конвертируется по курсу «монет за 1 TON».
  Курс задаётся в админ-панели (раздел «Коэффициенты») или переменной
  `COIN_MINOR_PER_TON` (в копейках: 35000 = 350 монет за 1 TON).
